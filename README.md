## 网页版与 Android App

网站通过 GitHub Pages 发布，电脑和手机浏览器均可打开。Android 是可直接安装的独立 APK，内置网站资源，支持离线整理收藏，适用于 Android 8.0 及以上。安装包在 GitHub Releases 发布，未上架应用商店。

**支持邮箱登录与 Supabase 跨设备自动同步。** 在网站、Android App 和电脑扩展中用同一个邮箱登录一次，以后手机“分享 → 拾光”、电脑按住空格再按 S 打开收藏窗口，保存后进入私有知识库，查看时再打开网站。无需每次填写表单或导入文件。离线时先保存本机：网站打开后同步、App 打开或再次分享时重试、扩展在浏览器运行时每分钟重试。未登录仍可本地使用。

登录邮件默认是一次性登录链接：网页可直接点邮件按钮；App / 扩展长按或右键邮件按钮复制链接，粘贴进登录框。各设备分别申请一封新邮件，链接只能使用一次。Supabase 默认邮件服务只向项目组织成员邮箱发送，个人使用请用该成员邮箱；开放给其他人需要配置自有 SMTP。真实收藏存放在 Supabase，行级权限只允许所属账号访问；公开 GitHub 仓库仅包含代码、公开客户端 key 和示例，不包含真实收藏、登录令牌或管理密钥。

清除设备数据或卸载前请确认同步完成，或导出备份。

## 主要功能

- 标题 / 标签 / 笔记 / 作者搜索，多个搜索词用空格分隔、同时匹配。
- 平台、标签、阅读状态和内容类型筛选；网格与列表视图。
- 特别关注、待阅读、标为已读、随机回看、笔记和标签编辑。
- JSON、CSV、HTML 浏览器书签导入；导入前检查勾选；URL 自动去重。
- Android 系统分享：在其他 App 选择分享链接到“拾光”，自动保存并返回原 App，无需打开网站或填写表单。
- Android 文件选择器导入、系统文件窗口导出备份，不申请全部文件或相册访问权限。
- AI 增强（可选）：新收藏自动生成一句话摘要与 ✦ 建议标签，支持按意思查找的语义搜索和每周 AI 回顾；需登录并配置智谱 GLM，未配置时自动停用。

首次进入显示醒目标注的示例库；点击“进入我的空白知识库”，或添加 / 导入真实内容即可退出示例。

## AI 摘要与语义搜索

登录后，网站会为新收藏自动生成一句话摘要与建议标签（卡片上以 ✦ 标注），点击 ✦ 标签即可采纳为分类；详情弹窗可一键采纳或重新生成。搜索框旁的「✦ 语义」开关提供语义搜索：按意思而不是关键词查找，例如搜“讲精力管理的文章”能命中对应收藏；语义模式下仍可叠加平台、标签、阅读状态筛选。侧边栏的「✦ 本周回顾」把近 7 天收藏与待阅读聚合成一份 AI 导读。已有收藏可在「备份与数据管理」中批量补齐摘要或重建语义索引，按钮均带进度与停止。

隐私与数据：生成摘要、标签时会把该收藏的标题、标签、笔记摘录与平台名发送给智谱 GLM（bigmodel.cn）接口；语义搜索会把搜索词发送给同一接口用于向量化。语义向量只保存在本机浏览器，不上传、不随备份导出；摘要与标签保存在你自己的 Supabase 数据库中，与收藏一起同步。登录前或未配置时以上功能全部自动停用，网站行为与现在完全一致；「清除 AI 数据」可移除本机向量与本条 AI 字段。

启用步骤（一次性）：

1. 在 [open.bigmodel.cn](https://open.bigmodel.cn) 注册并创建 API Key。摘要默认使用 glm-4-flash（免费），向量使用 embedding-3（约 0.5 元 / 百万 token），个人库全年成本通常在几元以内。
2. 配置密钥：`supabase secrets set GLM_API_KEY=你的key`，可选 `supabase secrets set GLM_MODEL=其他模型名`。
3. 部署两个边缘函数：`supabase functions deploy ai-enrich`、`supabase functions deploy ai-embed`。
4. 打开网站并登录，进入「备份与数据管理」点击「检测 AI 配置」。

两个函数与 link-preview 采用相同的防护：要求用户 JWT、来源白名单、逐用户限流、请求体上限；GLM 密钥只存在 Supabase 服务端环境变量中，不进入代码仓库、网页或扩展。

## 日常快捷收藏

电脑：安装 / 更新「拾光 · 一键收藏」扩展后，刷新原网页，在视频或文章页面**按住空格，再按 S**，或在网页右键选择「收藏到拾光…」。弹出的独立收藏窗口可选填「分类 / 标签」和「为什么收藏它」；留空也可以保存。多个分类用逗号分隔，在网站中以标签显示并可筛选、搜索。选中的网页文字会作为摘录保存。点击「保存收藏」或 Ctrl + Enter 后先保存到本机扩展，再自动同步；Esc 取消不会新增收藏。

空格 + S 仅在普通 HTTP / HTTPS 网页内生效，在输入框、文本编辑区中不触发。普通空格滚动保留。扩展安装或更新后，已经打开的来源网页需要刷新一次。备用快捷键 Alt + Shift + S 由浏览器扩展命令提供，也可在 Chrome 的 chrome://extensions/shortcuts 中调整。浏览器设置页、扩展商店等受保护页面不能采集。Chrome 原生分享菜单没有接入此扩展，使用快捷键或网页右键入口。

网站里的收藏封面和标题直接在新标签页打开原内容；「编辑」修改标题、分类和收藏原因；「详情」查看完整笔记、阅读状态和删除入口。列表视图同样支持这些操作。重复链接保留已有笔记和状态。扩展排队数据只有在网站成功写入后才移除。

Android：更新到 1.3.2，在原 App 中选择“分享 → 更多 → 拾光”。出现“已收进拾光”后返回原 App，之后打开拾光即可搜索。如果原 App 不提供分享链接，只分享图片或未包含 HTTP/HTTPS 链接，会提示未保存。可稍后在拾光补充标签和笔记。

**登录后跨设备同步。** 网站继续部署于 GitHub Pages，私有数据由 Supabase 保存。扩展右键 →「选项」中登录，App 和网站右上角「登录同步」中登录。

## 如何带入旧收藏

电脑上打开网站的“导入与采集”，下载并解压采集扩展。在 Chrome 的 chrome://extensions 或 Edge 的 edge://extensions 开启开发者模式，选择“加载已解压的扩展程序”。

1. 在扩展图标上点右键 →「选项」，打开旧收藏批量采集工具。然后在原平台登录，打开收藏 / 书签 / 稍后观看页面。
2. 滚动加载需要的条目，点击扩展“采集当前页面”。
3. 检查勾选链接，导出 JSON。
4. 回到拾光导入文件，重复链接会跳过，并保留已有笔记和状态。

扩展使用 activeTab、scripting、storage、alarms、contextMenus 权限，仅对 wuhy80.github.io 与拾光 Supabase 项目请求常驻访问；快捷键脚本在普通 HTTP / HTTPS 网页监听空格 + S，不读取密码或输入框内容；知识库归档脚本只匹配 /shiguang/ 路径。扩展只在你主动触发收藏时读取来源网页标题、链接和选中文字，收藏先保存到扩展存储，网站打开后自动归档；批量模式读取页面 DOM 中已加载的链接，不读取密码或 Cookie。动态 / 虚拟列表以及网页结构变化可能导致漏采，可分批采集或手动补充。未使用你的真实账号验证所有平台。浏览器采集扩展用于桌面 Chrome / Edge，Android App 可接收分享链接与导入备份文件。

## 开发与发布

本地运行：安装 Node.js，执行 npm start，打开 http://127.0.0.1:4178 。也可以双击 start.bat。Supabase 官方客户端已打包到 dist/supabase.js，无运行时 CDN 依赖。修改依赖后运行 npm ci 和 node scripts/bundle-cloud.cjs。

测试：npm test。导入、URL 去重、搜索、危险 URL 拒绝，以及 B 站跨子域 / 知乎专栏 / YouTube 页面链接采集均有自动测试。

推送 main 后，GitHub Actions 自动检查并发布 dist/ 到 GitHub Pages。Android 构建使用 JDK 17、Gradle 8.13、AGP 8.11.1 和 Android SDK 35，内置同一份 dist/。构建后验证 APK 签名，并发布 APK 与 SHA-256 校验值到 Releases。

Android 发布前需配置仓库 Actions Secrets：ANDROID_KEYSTORE_BASE64、ANDROID_KEYSTORE_PASSWORD。固定 PKCS12 签名密钥不进入源码；后续更新必须使用同一签名。发布新版本时同时增加 android/app/build.gradle 中的 versionCode 和 versionName；已存在的发布标签不会被自动覆盖。

可以在 Actions 页面手动执行网站或 Android 工作流。Android 成功构建不代表已经在你的实体手机上测试，安装后请先用少量收藏验证导入、分享与备份。

## 云端架构

数据库结构见 supabase/migrations/，library_entries 使用 (user_id,url) 主键、RLS 和删除标记。客户端本地记录待同步操作，成功确认后才移除；同步过程中出现的新编辑保留在队列。跨设备同一条笔记同时编辑采用最后一次成功写入；建议避免多端同时编辑同一条。重新收藏重复链接保留已有笔记，删除后再次收藏可恢复。客户端使用公开 publishable key；不要在 dist 或扩展中放 service_role / secret key。

项目部署时同时更新网站、App、扩展中的 cloud-config.js。Android 分享页只允许应用资源与指定 Supabase API，按来源绑定的消息仅传回保存结果。测试覆盖离线重试、上传中编辑、删除标记、重复链接和登录链接校验；数据库已在回滚事务中验证跨账号读写隔离。

- collector/：浏览器扩展，Chrome 加载此目录。

### Android 1.5.4 小悬浮球

在「我 → 手机快捷收藏 → 开启悬浮收藏球」允许系统悬浮窗权限。复制原内容链接后点球，选择分类并保存。小球可拖动，拖到左右边缘收成窄把手，点把手展开；长按关闭，也可从通知或设置关闭。仅主动点击后在前台读取剪贴板，不后台监控，不读取其他 App 的屏幕。按需开启，不开机自动启动；部分手机需允许后台运行以持续显示。


### Android 1.5.5 原 App 优先打开

点击收藏的封面、标题或详情链接时，先尝试对应平台的已安装应用，无法接收时回退系统默认处理。支持小红书、B站、知乎、抖音、YouTube、GitHub 的应用包；传递原始链接，不丢弃短链接参数或访问令牌。网站在普通浏览器中仍遵循浏览器和系统的链接设置。未改变收藏采集方式。


### Android 1.6.0 收藏跟随试用

修复小红书 xhslink.cn 来源识别及路由，长笔记链接优先使用官方 xhsdiscover://item 路由。

### Android 1.6.1 收藏跟随排查与修复

修复页面更新及重复成功提示导致等待任务被反复推迟；使用固定检查及绝对期限。补充按钮角色描述、数量标签与点击容器直接子控件识别。仅用被点击控件状态或成功提示确认，避免其他已收藏卡片触发。开启非重要控件事件以支持嵌套按钮，监听范围仍仅为小红书和B站。

我页面区分应用授权、系统服务连接，并显示带时间的最近阶段；识别收藏时有短提示，超时、分享/复制失败、窗口未获得前台焦点或原链接校验失败均显示原因。没有原内容链接不保存。覆盖安装后确认 1.6.1，在无障碍设置关闭再开启服务以应用新事件配置，然后进入详情页收藏（B站需确认收藏夹）。自动化规则和定时回归在 CI 检查，第三方 App 真机兼容性仍待用户设备验证。


### Android 1.6.2 复制收藏来源与小红书直达

分享和悬浮球复制收藏共用 ShareLinks 解析整段文案，排除常见中文标点，补全常见无协议短链接，平台链接优先于附带普通网址；多个平台链接由用户选择，分类窗口显示来源。已知平台以真实域名纠正旧归属，原链接与分类原因保留。

点击小红书短链接时异步解析受限 HTTPS 跳转，取得真实笔记路径后使用 xhsdiscover://item/<id> 打开原 App，并保留访问参数。网络请求不带 Cookie，仅限小红书域名，限制次数和超时。失败提示重试，不再用小红书 WebView 当作笔记直达成功；用户仍可主动选择浏览器打开。不会将账号主页或跨域跳转作为原内容。直接覆盖安装 1.6.2；该流程不需要无障碍收藏跟随。真实手机 App 行为仍需设备验证。


### Android 1.6.4 本地状态识别与弹窗恢复

参考[小星记账官方实现原理](https://cxincx.com/support/auto/2.html)所公开的无障碍读取界面→本地识别→弹窗机制，改进原有收藏跟随，不使用其未公开源码。仅处理小红书和B站的可识别界面，无 Root、无截图/OCR。已有复制收藏、小红书原链接打开和云同步流程继续沿用。

同时监听点击、选中、页面/窗口变化，在支持平台前台按500ms间隔对比短时按钮状态。仅单个可识别收藏控件从未选中变为选中时触发状态识别；同一可点击按钮的子标签合并。需要近期对应按钮点击（缺失来源的点击或明确收藏成功事件也可确认），防止初始加载误判。页面变化先于点击时，仅短时保留700ms待确认状态。首次进入已收藏页面、取消收藏、重复选中、过期快照、窗口/平台切换和滚动均不触发新增状态。原有点击→等待收藏成功仍保留，B站必须先确认收藏夹。

确认后只操作分享与复制链接，取得本次原平台的内容链接，再显示现有分类/原因窗口。系统阻止后台 Activity 时，用无障碍提示卡让用户点击继续；45秒无人操作即取消。没有新原链接不保存，不用页面标题或主页代替。在“我→查看检测记录”可查看/复制最近12条本机阶段记录（不含页面树、正文或链接）。

覆盖安装后建议在系统中将拾光无障碍服务关闭再开启，以重新加载事件和多窗口配置。检测测试、Java编译和APK构建不能替代真实手机版本验证；如某版本不暴露按钮信息，本方案仍可能无法识别。


### Android 1.6.5 图标按钮适配与不中断的分享引导

修复仅按文字寻找分享/收藏控件的局限：补充严格限定包名和语义资源ID的控件匹配、长按收藏事件、与近期点击关联的明确收藏成功事件。增加B站HD包名。找到唯一候选后先使用无障碍点击；失败时仅对已识别控件的实际小范围边界中心尝试触摸，不用固定屏幕坐标。

确认收藏后未找到分享按钮时不立即退出，保留30秒引导原App分享/⋯；菜单出现后继续复制链接和分类。新增“我→适配本机按钮”，让用户在内容页明确记录下一次收藏/分享点击。规则只存控件ID/类/结构路径/相对位置，不存正文或链接；分享候选在出现复制链接菜单后才持久化。后续要求唯一候选、相同根/控件类型、方向、相对位置容差6%，不匹配时转回引导。按钮改版或不同布局需要分别重新适配。

适配收藏时应选择尚未收藏的内容，在原App完成收藏；适配分享时会继续取得当前内容链接，再展示选填分类/原因，只有确认保存才写入。覆盖安装后重启无障碍服务以加载长按事件和触摸能力。本机未连接手机，只有自动化规则测试、编译和发布验证，实际按钮可见性仍需手机检验。


### Android 1.6.6 收藏夹滚动与原内容检查

根据1.6.4实际记录，移除收藏确认等待期间遇到任意滚动立即失败的分支。滚动不重置收藏确认定时器；平台确认后，必须核对原窗口及本地标题/文本锚点才自动打开分享。收藏夹窗口、同窗口弹层或滑到下一条内容都不直接当作原页面；无法核对时等待原内容返回，确认后的等待最多到本次操作17秒，随后转为手动分享引导。未确认收藏仍沿用原15秒截止时间。

锚点优先可见标题/标题控件，其次可见非控件的实质文本，仅放在内存，不存储到检测记录或上传。没有可用锚点不自动猜测原内容，由用户回到原内容后点分享继续。纯Java回归测试覆盖收藏夹滚动、返回原页面、下一条视频拒绝、未知页面和固定超时。手机实测仍需新版记录。


### Android 1.6.7：扩展平台适配

“我 → 适配本机按钮”可选择小红书、B站、知乎、抖音、YouTube。监听范围与菜单同时扩展；支持 B站不同包及抖音极速版，但记录的按钮规则仍按实际应用包独立保存，不能把 B站规则误用于知乎等平台。新增平台使用对应的原内容链接校验，拒绝其他平台链接、首页、个人主页和播放列表页。

覆盖安装后，将系统中的拾光无障碍服务关闭再开启。依次选择平台，记录其分享按钮和收藏/保存按钮。YouTube 对应“保存到播放列表”或“稍后观看”，需完成原平台确认。分享按钮必须通过“复制链接”菜单验证；原链接取得后仍需你确认分类并保存。常见语义按钮会自动识别，自定义适配是图标未识别时的补充，并非每次收藏都要重新配置。平台更新或不同页面的控件结构改变后，可能需重新记录。

目前完成规则测试与编译验证，未替代实际手机上的跨平台实测；支持平台列表不意味着每个 App 版本都保证成功。


### Android 1.6.8：小红书手机收藏信息

手机本地预览增加小红书公开笔记，支持 `xhslink.cn` 与 `xhslink.com` 短链。每一跳都验证小红书域名并保留访问参数，优先匹配原笔记ID的标题和首图，再读取OG元数据；默认不携带账号Cookie。遇到要求登录的笔记，可在“我 → 登录小红书补全信息”中由本人同意并登录；之后仅在本机向小红书使用该网页会话，不上传凭据，亦可关闭授权。不执行页面脚本。响应大小、跳转次数和等待均有限制。

分类保存会等待正在请求的元信息（最多12.5秒），避免在预览尚未返回时永久保存域名占位标题。旧收藏可在联网打开知识库后尝试补全封面或域名占位标题；不会覆盖已有自定义标题、封面、分类或原因，沿用现有云端同步到电脑。限制访问、要求登录或不公开信息的笔记无法保证补全；保留原链接，拒绝用登录页标题冒充笔记。

收藏跟随校验链接时会保留分享文字中明确的笔记标题，例如“【标题 - 作者 | 小红书】”，避免校验时丢弃标题而只剩域名。


### Android 1.6.9：复制菜单与知乎标题

针对YouTube“已识别收藏→未能复制原内容链接”的记录，允许明确标为复制链接的整行按钮，不再因宽度超过屏幕60%直接拒绝；依旧拒绝整页容器。读取系统分享面板仅在正在取链接或适配分享菜单期间生效，复制后仍以原平台链接及剪贴板时间戳校验。

知乎保留分享前缀标题，并加入手机本地OG/title读取；YouTube使用公开oEmbed标题并保留直接封面回退；抖音增加公开网页预览及modal_id内容链接校验。新预览请求不携带账号Cookie，仅允许同平台域名跳转，限制大小与时间。旧域名占位标题可在联网打开知识库后尝试补全，平台拒绝公开访问时可能仍无法取得标题。

覆盖安装后重启拾光无障碍服务。已有日志尚无抖音失败阶段，不能据此断言同一修改已解决其所有问题；仍需手机实测，并用带平台名的新记录继续定位。
